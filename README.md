## World and measurements

North is row 0. B1=(3,0), B2=(9,0), B3=(15,0), B4=(21,0); warehouse=(0,15). Ships moor offshore immediately north of their apron at (x,-1). A worker on the apron is adjacent to the ship; B1/B4 apron cells are unsafe at storm onset.

One `random.Random(seed)` pre-generates all exogenous events. Each tick processes arrivals, FIFO docking, the 20-tick berth bulletin, Lookout warning/storm onset, Master turn if due, one action per worker, empty-ship departures, and measurements. Worker priority rotates. Workers cannot enter cells with three occupants. A Lookout warning occurs five ticks before onset; remembering policies retain it until the 15-tick storm ends. Onset knock-outs last 20 ticks and lose carried cargo.

`cargo_delivered` counts warehouse drops. `avg_ship_wait` is arrival-to-docking delay across all arrivals, with still-undocked ships censored at tick 600. It is a restricted mean, not full eventual wait. `crowding_violations` counts cell-ticks with more than three workers. `storm_knockouts` counts worker-onset events. Picked units are conserved among delivered, carried and lost cargo.

Baseline waits. Reflex uses a current occupied-berth signal and current warning only. Model-based stores warning expiry and target state and uses remembered berth information. Utility scores `0.8*cargo - 1.2*distance - 0.8*other_assignments - 0.4*nearby_workers - 100*risk + 3*same_target`; remembered unsafe berths are also excluded. Weights and safety-adjusted policy selection use development seeds 1-10 only. Utility is the best rule-based controller under deliveries minus 20 per knock-out and is the fallback.

## Controller and safety

The model receives only the text report and system prompt. It has no simulation objects or executor access. The parser checks the three ReAct JSON fields, then handles literal `Action` calls as AST data and never uses eval. Validation enforces action names, argument types, entity existence, worker budgets and storm safety. Only a current fact line or a checked absent-ship statement can be published as the Final Report. Thought is a diagnostic decision summary, not a player-facing factual channel.

The allowlist is `assign_workers(berth,n)`, `hold_ship(ship_id)`, `warn_storm()`, `close_harbour()` and `release_cargo(ship_id)`. At most three actions are permitted; the prompt asks for one. After two correction retries, the controller falls back to utility. The specified list has no no-op, so an empty initial state can legitimately need fallback.

Sensitive close/release actions default to blocked. `--human-approval` requires a person to type `APPROVE` for each exact order; no manifest, crew note, player message or model text can approve it. Holds last 20 ticks. Releasing cargo removes an administrative hold; it does not create or deliver units. Closing prevents new docking. Input text is JSON-escaped and marked untrusted; the instruction hierarchy is separate from code-side permission enforcement.
